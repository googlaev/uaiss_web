# UAISS — Инструкция по развёртыванию (прод)

Разворачивается как Docker-контейнер (`Dockerfile` + `docker-compose.yml`), слушающий `:8000` внутри хоста. TLS/домен (сейчас `https://bot.codle.ru`) обеспечивает внешний реверс-прокси — он не входит в этот репозиторий и здесь не настраивается.

Для локальной разработки (Python напрямую, Android Studio) см. `docs/SETUP.md`, разделы 1–4. Этот файл — только про сервер.

---

## 1. Требования к серверу

- Docker + Docker Compose plugin
- Внешний реверс-прокси с TLS (nginx/Caddy/Traefik), проксирующий `https://<домен>` → `http://127.0.0.1:8000` — настраивается отдельно от этого репозитория
- Исходящий HTTPS наружу (SMTP Gmail, `botapi.max.ru`, Firebase FCM)
- `cap_add: SYS_TIME` разрешён (используется для `ntpdate` при старте контейнера — критично для планировщика уведомлений, см. `docs/ARCHITECTURE.md`)

## 2. Первое развёртывание на новом сервере

```bash
# 1. Получить код
git clone <репозиторий> appUAISS && cd appUAISS
# или scp/rsync, если без git

# 2. Создать секретные файлы — их НЕТ в git (.gitignore), но Docker ожидает
#    их существования на хосте ДО первого запуска (иначе вместо файла
#    подставится пустая директория и бэкенд упадёт с IsADirectoryError)
cp config.example.json config.json
touch exams.db
echo "{}" > serviceAccountKey.json   # или реальный ключ Firebase, если нужен push

# 3. Заполнить config.json реальными значениями
#    - smtp.user / smtp.password (Gmail App Password)
#    - auth.jwt_secret_key — сгенерировать: python -c "import secrets;print(secrets.token_hex(32))"
#    - max.enabled / max.token — если нужны уведомления в MAX (см. docs/SETUP.md, "Настройка MAX-уведомлений")

# 4. Собрать и запустить
docker compose up -d --build

# 5. Проверить
docker compose logs -f
docker compose ps
curl http://localhost:8000/docs
```

**Дальше:**
- Настроить внешний реверс-прокси на `127.0.0.1:8000` под нужный домен + TLS-сертификат.
- Если нужно мини-приложение MAX: зарегистрировать `https://<домен>/maxapp/` в `business.max.ru/self` → Чат-боты → ваш бот → Настройки → URL (см. `docs/SETUP.md`, «Регистрация мини-приложения MAX»).
- Если нужны уведомления в MAX-группу и еженедельный отчёт статусов: см. раздел 5 ниже.

Полный список переменных `config.json` и их назначение — `docs/BACKEND.md`, раздел «Конфигурация».

## 3. Обновление уже работающего прода (деплой новой версии)

```bash
# 1. Забрать актуальный код
git pull
# или вручную заменить test.py / new_uaiss.html / www/index.html на новые версии

# 2. Сверить config.json с config.example.json — не появились ли новые ключи
#    (например, секция max.group_chat_id/group_notify_days/weekly_report_*
#    добавлена в этом репозитории позже исходного релиза). Отсутствующий
#    ключ не ломает запуск (код читает его через .get() с дефолтом), но для
#    использования новой функции значение нужно вписать явно.

# 3. Пересобрать и перезапустить контейнер
docker compose up -d --build

# 4. Проверить логи — не упало ли на старте
docker compose logs -f --tail=100
```

> `config.json` перечитывается только при старте процесса — правка файла без `docker compose restart`/`up -d` не подхватится.

**Быстрая проверка после деплоя:**
- `GET /docs` отдаёт Swagger UI
- `POST /api/v1/auth/login` с тестовым или реальным логином возвращает токен
- Если правился фронтенд — убедиться, что `new_uaiss.html` и `www/index.html` синхронизированы (это два разных файла, см. `docs/ARCHITECTURE.md`, карта директорий)

## 4. Откат на предыдущую версию

```bash
git log --oneline -5                 # найти коммит/тег, на который откатываемся
git checkout <commit> -- test.py new_uaiss.html www/index.html
docker compose up -d --build
```

`exams.db` и `config.json` откатом не затрагиваются — они на хосте, а не в образе. Если проблема именно в миграции БД — восстановить `exams.db` из бэкапа (регулярный бэкап этого файла в репозитории не настроен, делать отдельно).

## 5. Настройка MAX-уведомлений после деплоя (если ещё не сделано)

Токен и включение канала — в `config.json` (см. раздел 2 выше и `docs/SETUP.md`). Дополнительно, если нужно дублирование уведомлений в групповой чат и еженедельный отчёт статусов:

1. Добавить бота в нужную группу/канал MAX (бот сам ничего туда не пишет — молчит и только слушает).
2. Посмотреть лог бэкенда (`docker compose logs -f`) — при добавлении бота появится строка `🔔 MAX: бот добавлен в групповой чат/канал, chat_id=...`. Если бот уже состоял в группе раньше — такая же строка (с текстом «обнаружен групповой чат/канал») появится сама при первом сообщении в этой группе от кого угодно.
3. Вписать этот ID в `config.json` → `max.group_chat_id`, при необходимости поправить `max.group_notify_days` (по умолчанию `[30, 3, 1]`) и `max.weekly_report_*` (по умолчанию понедельник 10:00).
4. `docker compose up -d --build` (или `restart`, если менялся только `config.json`, без кода).
5. Проверить сразу: `POST /api/v1/max/weekly-report/send` под admin-токеном — отчёт статусов придёт в группу немедленно, не дожидаясь понедельника.

Подробности логики — `docs/BACKEND.md`, раздел «MAX-уведомления».

- [ ] Если добавлены новые ключи конфига — `config.example.json` обновлён
- [ ] `docs/*.md` актуализированы под изменение (если меняли поведение API/конфига)
- [ ] `config.json`, `exams.db`, `serviceAccountKey.json` существуют на сервере как файлы (не директории) перед `docker compose up`
